# 会议工作区与真实流式总结

状态：实施与验证中；2026-09-28。基线 `4f60a98`，分支 `codex/meeting-section-summary`。

## 范围

统一简体中文，左侧保留开始会议、搜索、历史及会议菜单，右侧在所有窗口宽度统一使用“会议转写 / 会议总结”页签。开始区包含会议标题、音频设备和麦克风音量测试；录制沿用现有暂停/继续/结束接口。隐藏设置、模型、更新、关于、导入与独立笔记入口，旧路由返回会议页面。

## 流式链路与正确性

OpenVINO 生成回调通过本机 HTTP SSE 发出正文。Node 按 UTF-8 边界解析完整事件、累计原始响应，过滤完整及跨分片的思考标签；只有正常 stop、完整终止标记、tokenizer 用量相符且非空才提交检查点。模型、采样、提示词、切片算法及最终数据库路径保持原有配置。

Node 通过 stdout 向 Rust 发送独立的进度快照及正文增量；Rust 缓存快照并发布 `meeting-summary-progress`，`get_summary_progress` 可按历史会议或当前录制查询。前端先订阅后取快照，按任务、请求和序号隔离，独立的低频查询恢复漏事件并核对数据库提交。模型生成完成是“正在保存”，真实 SQLite 成功后才是“已完成”。重新打开只读快照及原有数据库；不新增崩溃自动续跑。

时间范围来自 ASR 段。部分文本使用其覆盖段的完整边界；上一块 buffer 不进入本块完成范围。尾部预算切分携带源段映射，章节材料携带所用笔记的来源区间，间隔不会合并为整场连续音频。完整处理的来源段边界用于“已整理至”。

正文事件每 300ms 合并一次，阶段变化立即发送。草稿使用轻量只读文本，已完成笔记按需展开；用户向上滚动后不抢位置。完整 state.json 从原有 250ms 无条件写入改为阶段及两秒检查点，独立 progress.json 同样节流，保留原子替换。

## 内容质量与性能边界

本次短输入的串行流式/非流式正文一致，只证明该输入下输出保持一致，不构成普遍准确率结论。完整重放仍把到期且待讨论的续租写成已续租，遗漏末尾写报告并提交的要求，并将部分闲聊转成待办；23条待办不等于23项真实交办。原始输出未人工改写，本次不修改提示词或以流式动画宣称准确度改善。

纯文本重放的模型RSS峰值2949.60MiB、私有提交峰值2278.93MiB，可用内存最低1812.19MiB，模型CPU中位27.55%、P95 37.5%。此数据不包含真实录音负载，也不能把RSS视为独占物理内存；原速完整结果另列。
