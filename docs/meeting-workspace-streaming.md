## 范围

统一简体中文，左侧保留开始会议、搜索、历史及会议菜单，右侧在所有窗口宽度统一使用“会议转写 / 会议总结”页签。开始区包含会议标题、音频设备和麦克风音量测试；录制沿用现有暂停/继续/结束接口。隐藏设置、模型、更新、关于、导入与独立笔记入口，旧路由返回会议页面。

原有简单音量接口输出模拟正弦数值，复核后改接现有CPAL真实采样实现，仅测试当前选中的麦克风。采样流归属于专用线程，停止测试时等待线程退出并释放设备，设备不可用会返回错误。前端卸载时释放订阅与测试流；开始会议前同样等待释放。此修正不改变录音或模型生成算法。

## 流式链路与正确性

OpenVINO 生成回调通过本机 HTTP SSE 发出正文。Node 按 UTF-8 边界解析完整事件、累计原始响应，过滤完整及跨分片的思考标签；只有正常 stop、完整终止标记、tokenizer 用量相符且非空才提交检查点。模型、采样、提示词、切片算法及最终数据库路径保持原有配置。

Node 通过 stdout 向 Rust 发送独立的进度快照及正文增量；Rust 缓存快照并发布 `meeting-summary-progress`，`get_summary_progress` 可按历史会议或当前录制查询。前端先订阅后取快照，按任务、请求和序号隔离，独立的低频查询恢复漏事件并核对数据库提交。模型生成完成是“正在保存”，真实 SQLite 成功后才是“已完成”。重新打开只读快照及原有数据库；不新增崩溃自动续跑。

时间范围来自 ASR 段。部分文本使用其覆盖段的完整边界；上一块 buffer 不进入本块完成范围。尾部预算切分携带源段映射，章节材料携带所用笔记的来源区间，间隔不会合并为整场连续音频。完整处理的来源段边界用于“已整理至”。

正文事件每 300ms 合并一次，阶段变化立即发送。草稿使用轻量只读文本，已完成笔记按需展开；用户向上滚动后不抢位置。完整 state.json 从原有 250ms 无条件写入改为阶段及两秒检查点，独立 progress.json 同样节流，保留原子替换。

## 内容质量与性能边界

本次短输入的串行流式/非流式正文一致，只证明该输入下输出保持一致，不构成普遍准确率结论。完整重放仍把到期且待讨论的续租写成已续租，遗漏末尾写报告并提交的要求，并将部分闲聊转成待办；23条待办不等于23项真实交办。原始输出未人工改写，本次不修改提示词或以流式动画宣称准确度改善。

原生长测也遗漏3956.85秒源段中“写一份详细报告并交给对方查看”的要求，且将其他企业的闲聊写成“调查并优化富士康的薪资结构”等任务；46条勾选项不代表46项真实交办。章节之间仍有重复与矛盾，正常stop只说明生成链路完整结束，不说明语义准确。见长测目录 `QUALITY_REVIEW.md`。

原生长测系统CPU中位39.08%、P95 75.37%，5秒采样可用内存最低1385MiB；1秒播放监测最低约1365MiB。模型RSS峰值2690.09MiB、私有提交峰值2249.57MiB。系统磁盘写入中位1.74MiB/s、P95 11.85MiB/s，磁盘队列中位0、P95 1。这些是整机读数，包含录音、ASR、系统及复制交付包等活动，不能归为总结单项开销；没有同机同输入的流式关闭对照，不声称性能零退化。

内存诊断：原速长测中WebView私有内存5分钟中位从约236MiB增长到约900MiB，会后回落至约451MiB；Node后半程稳定在约75MiB。加速重复读取完整进度时，单个渲染进程从约47MiB临时增长至约346MiB，强制GC后回到约47MiB，1500次读取后额外保留JS堆2356字节。此实验确认了可回收的快照分配开销，未证明完整原速过程没有任何内存问题；因此追加 `03c382a` 条件快照优化，并另行对照传输量和分配峰值。最终包以相同长会议进行1500次条件快照读取，返回正文从216748500字节降至6000字节；单个渲染进程读取后约52.4MiB，GC后约50.3MiB，额外保留JS堆19472字节。初次、旧序号、不同任务及保存阶段变化均验证仍返回完整快照。66分钟原速数据属于优化前版本，不能改标为最终构建的恒定内存结果。

最终构建还在暂停的测试会议中进行了三轮原生总结页签压力回放，每轮14段笔记、5章、985个事件，共2955个事件。使用已生成内容，仅向界面发送事件，不运行模型或改写保存纪要；结束后正常收尾测试会议，再核对历史纪要。每轮GC后JS堆约7.37、7.87、7.46MiB，应用所属WebView合计私有内存约247.67、248.41、249.18MiB；第三轮相对第一轮保留JS堆增加94784字节，未观察到逐轮持续增长。该隔离实验验证界面对象生命周期，不能替代另一轮包含ASR、分人和模型的原速整机资源对照。

纯文本重放的模型RSS峰值2949.60MiB、私有提交峰值2278.93MiB，可用内存最低1812.19MiB，模型CPU中位27.55%、P95 37.5%。此数据不包含真实录音负载，也不能把RSS视为独占物理内存。
