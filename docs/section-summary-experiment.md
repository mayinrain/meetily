# 分段笔记与逐章汇总实验

实验分支：`codex/meeting-section-summary`，基于 `codex/meeting-realtime-summary` 的 `e2086a7`。保留 SenseVoice、VAD、Community-1、说话人批次和保存原始转写的实现；只更换自动纪要工作流。旧正式分支与录音结果不被覆盖。

流程参照 RugGear `codex/session-only-speaker` 的固定提交 [4b2cb4b](https://github.com/omnimind-project/RugGear-Meeting/tree/4b2cb4b31268588365aa04a2669f7e0c517d7115)，重点是 `MeetingCompression.kt`、`OverflowFinalSummary.kt` 和 `MeetingSummaryService.kt` 的本地路径，未移植 Android 采集、ASR 或分人代码。

## 行为

1. 接收现有完整且冻结的带说话人转写批次，累计文本。新增可读转写超过 1200 字符时，继续到门槛之后首个句末边界；没有句末则取当前全部新增文本。下一块附上前块末尾约 300 字符原文，缓冲只帮助理解，不重复推进游标。
2. 每块按通用模板写笔记：内容概览、主要讨论、结论、明确待办、未决问题。输出上限 1280 token；不再提取短事实补丁，也不做四条旧事实召回。笔记、来源字符偏移、输入输出和耗时分别持久化。
3. 停止后取消未完成的会中笔记；原文仍在游标之后，由最终整理接管。等待原有说话人任务提交最终批次。
4. 已保存笔记不足两块，或者完整转写不超过 1200 字符时，完整转写直接生成（上限 1800 token）。直接输入超预算会报错，不静默截断。
5. 至少两块时，先补齐未处理尾文，再收集全部笔记的同名章节，每章单独生成（上限 2048 token）。章节超输入预算只拆该章节，至多三轮局部归并；模型不再缩短时保留全部输出，最后直接拼装各章，不再全文重写。
6. 每次生成保存请求检查点；仅完整、非空成功结果可按实际请求、阶段、模型文件身份复用。失败或取消不会把半截输出标成完成。当前桌面仍不提供崩溃后的自动续跑入口；检查点并不等于自动恢复。

保持相同的 Qwen3.5-4B Q4_K_M、llama.cpp b10809、CPU 两线程、6144 上下文和非思考采样参数，以比较流程变化。由于目标机只有 8 GB，输入预算使用实际 tokenizer 并预留输出空间，没有照搬对方的 8k 输入上限。短会议成品及长会议章节正文保存到现有 SQLite，保留原会议标题，不另调用模型改标题。

该实验使用 `section-notes-v1` 标识。旧 `fixed-facts-v1` 结果仍可读取。会后 120 秒继续作为达标线；为观察完整质量和实际等待，实验硬截止放宽到 20 分钟。`within_post_stop_target` 只有完整成功且工作流收尾不超过 120 秒才为真；最终桌面指标还需要包含点击停止后的 AAC/ASR 收尾。超过达标线不表示性能通过。

模板与参考分支一致，以事项组织正文，不按发言人分组；这轮不额外引入人物立场图谱。较丰富的笔记不能证明更准确，仍需对照原文检查数字、条件、案例与决定的区分。

## 2026-09-24 请求超时修复

`section-win-full-02` 的第五份会中笔记在 304.364 秒报 `TypeError: fetch failed`，模型进程当时仍在。失败不推进游标，已有 4 份笔记覆盖 4153 字，后续内容留到会后，文件锁故障前已有 3847 字积压。这是独立于观察干扰的真实传输问题。

用实际 `createGenerator`、600 秒应用期限和 310 秒延迟的本地 HTTP 服务复现：Node 22.23.2 / Undici 6.28.0 在 301.089 秒抛出 `UND_ERR_HEADERS_TIMEOUT`，应用信号尚未取消，服务端仍在等待正常返回。原生 fetch 的独立 300 秒响应头期限早于应用上限。将本地模型 JSON 请求改为 Node 内置 HTTP，并继续由原有 AbortSignal 控制期限和取消；模型、提示词、上下文及工作流均不变，没有增大 600 秒上限。

新增快速回归加速 HTTP 客户端计时器，保留实际服务端延迟及应用期限：修复前 0.784 秒失败，修复后连同既有取消/截断/覆盖等测试共 13 项通过。另行等待不加速的 310 秒回归结果及 Windows 发布构建；完整音频须使用新编号重新验证。
