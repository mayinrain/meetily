每场会议开始时读取一次设置，记录到该场 `selected-model.json`，通过子进程环境固定会中笔记、尾部和最终章节的模型。会中改变设置不改变本场模型。手动重新生成使用当时选定的模型，读取数据库中的完整原文及可用的说话人结果，沿用同一流式链路和数据库校验；原文超出上下文时先拆为笔记，再逐章总结。

## 连接及重试

使用用户提供的 provider SSH 身份连接目标机器，转发只监听 `127.0.0.1`，开启严格主机密钥校验。先转发远端 9000 网关，读取实际模型端口，再建立该端口的转发并核对模型 ID。不会把动态端口写死，不停止或重启远端共享模型服务。工作进程结束时只关闭自己创建的 SSH 子进程。

Windows 连接配置在当前用户应用数据目录 `intranet-model.json`，密钥和已核验的主机公钥存放于 `intranet-ssh`，目录权限限制为当前用户及 SYSTEM。密钥不进入源码、提交或程序交付包。会中改设置不操作其他场次或远端服务。

原有生成器没有网络抖动重试。本次内网路线对连接断开、超时、流中断和 HTTP 408/425/429/500/502/503/504 增加最多 3 次自动重试，退避为 2、5、10 秒。每次重连重新发现远端端口；每次请求尝试最多 180 秒，单个生成任务仍受原有 600 秒期限约束。取消会立即中止请求和退避；参数错误、认证 HTTP 错误、token 预算终止及 tokenizer 不一致不重试。

重试前通过新请求标识清空当前半段草稿，保留已完成笔记和 ASR 来源范围；本段来源游标只有完整成功时推进。界面显示重试次数与等待时间。超过次数则明确失败，保留原文，未完成会中分段仍由原有会后流程接管。不自动切换到内置模型，不把失败半段存为已完成内容。

内置模型的提示词、采样参数、600 秒请求期限及无网络重试行为保持原状。两条路线均校验真实 tokenizer、正常 stop、完整流终止及来源覆盖；不因采用较大模型而跳过完整性校验。

## 35B 重复输出修复

原失败请求为“主要讨论”的第二组材料，1508 个输入 token、2048 个输出 token。直接在模型服务器本机重放，排除了前端、Node 流解析和 SSH 的干扰：

| 唯一变量 | 结束原因 | 输出 token | 同一句出现次数 | 耗时 |
|---|---|---:|---:|---:|
| 原参数，流式 | length | 2048 | 37 | 44.39 秒 |
| 改为非流式 | length | 2048 | 37 | 44.31 秒 |
| 关闭 prompt cache | length | 2048 | 37 | 46.56 秒 |
| presence_penalty 从 0 改为 1.5 | stop | 680 | 1 | 15.58 秒 |
| 同参数复测 | stop | 680 | 1 | 15.48 秒 |

因此，此次故障是模型在原解码参数下进入重复循环，并非页面重复拼接或流式协议问题。只对内网 35B 使用 `presence_penalty=1.5`，仍保持 temperature=0、repeat_penalty=1、原提示词和 token 预算。参数值也与 [Qwen3.5 官方模型说明](https://huggingface.co/Qwen/Qwen3.5-35B-A3B) 中通用非思考任务的 presence penalty 建议一致；这里没有照搬整套采样配置。

随后串行比较新参数的非流式和流式调用，两者均正常 stop、562 个输出 token，正文 SHA-256 一致。不同时间的同输入复测曾输出 680 个 token，不能据此承诺跨请求的字节级确定性。

撤销临时的 768 输入预算绕行，章节分组恢复 1536。内网生成器同时检查连续四次相同的长正文行（至少 24 个字符，忽略列表编号和空白），发现后中止请求并明确报错，不自动按网络故障重试，不去重后伪装成功，不推进来源游标。该检查针对已复现的循环形态，并不保证识别所有语义重复。真实失败 SSE 回放也触发此检查：第四次连续重复被拒绝，最终成功检查点为零；分隔于此前其他段落的同一句不计为连续循环。正常短占位文案、不同数字的事实和分隔于不同章节的相同内容不受影响。内置 1.7B 保持原参数及行为。

复测输出能正常结束，但仍有细节省略，例如该组材料中的 16 元/小时、工作一周可离职未出现在压缩正文中；输入笔记自身已有的归类错误也未被纠正。重复修复不等于准确度修复，完整回归的内容质量另列于下文。
