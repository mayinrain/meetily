# 固定工作流提交修复与验证

2026-09-24。本文件保留独立摘要实验的历史验证记录。当前集成分支已将同一解析、检索、事实修改和提示词提取为应用共享模块，实际录音接入见 [实时会议纪要集成](../../docs/realtime-meeting-workflow.md)。下面的模型指标仍是历史独立实验，内容质量未通过，结果需要人工核对。

## 运行方式

每个完整批次到达后，程序召回最多四条相关旧事项，调用一次本地模型，原子保存新增和修订，最后排版为讨论、决定、行动、待确认。没有 Agent 工具循环、模型重试或会后全篇重写。

普通四章节只新增，由程序分配编号。修改必须在“修订”章节指定本批已提供的 F 编号，默认保留分类；“修订 行动”等标题可明确改分类。适配器兼容新条目误带编号、编号行漏列表符号和“已有 F0001”前缀，不改变事实正文。未知或不可见修改编号、重复修订、截断及中止整批拒绝。

该边界保护新增事项不因误写编号而覆盖旧事，不判断合法修订是否符合原文。模型也可能把实际变更当新增，或在整条替换时遗漏未变属性。

## 本地复现

使用 Bun，在本目录执行；这套固定工作流仅使用 Node 内置模块，不依赖 Pi：

```sh
bun build workflow.ts --target=node --outfile=workflow.mjs
bun check-workflow-submissions.ts
bun check-workflow.ts
```

构造输入和捕获回复在 fixtures/workflow-*.json。它们是虚构任务诊断，不含完整真实会议转写。捕获回复回归前六次按原样，第七次旧标题从“行动”转换为新“修订”协议，事实正文不变；另用真实失败的“已有 F0001”回复原样验证前缀兼容。测试不调用模型。

HTTP 回归验证每批一次串行调用、无工具或未来原文、旧事项修订、无效/截断回复原子拒绝、失败后继续、截止中止不写入，以及失败批次仍计入未提交积压。合法提交率不等于语义正确率。

本地模型服务准备好后，可复现两个原时间1x测试：

```sh
MODEL_PROFILE=qwen4-off bun workflow.mjs fixtures/workflow-memory.json /tmp/workflow-memory-new batch-facts 361 120
MODEL_PROFILE=qwen4-off bun workflow.mjs fixtures/workflow-mixed.json /tmp/workflow-mixed-new batch-facts 121 120
```

输出目录必须全新。服务默认 http://127.0.0.1:18791，提供 llama.cpp 的 /apply-template、/tokenize、/v1/chat/completions；可用 MODEL_URL 指定本机服务。目标验证环境为 llama.cpp b10809、Qwen3.5-4B Q4_K_M、非思考、CPU2、6144上下文、650输出、seed42及 model-profiles.json 中原采样参数。

## 真机结果

Windows i5-11300H / 8GB。每组冷启动、清空事实库、原时间1x输入，停止后最多120秒收尾。输入已有转写和预计算说话人，不含 ASR/Community-1 并发。

| 样本 | 保存批次 | 停止后全部保存 | 停止时未提交 | 最终未提交 |
| --- | ---: | ---: | ---: | ---: |
| 旧任务，10段、361秒 | 7/7 | 17.18秒 | 2/10 | 0 |
| 混合操作，7段、121秒 | 3/3 | 24.75秒 | 3/7 | 0 |
| 真实开场，94段、314.47秒 | 5/5 | 60.27秒 | 19/94 | 0 |

停止时未提交均是刚发布的最后一批，没有另外排队的批次。两组构造测试的逐批处理均在下一批之前结束。开场累计处理248.16秒，上一轮同输入工作流241.55秒；收尾由51.76增至60.27秒，未取得提速。开场模型+Node RSS峰值3.142GiB，系统可用内存最低2.745GiB，不代表ASR/C1并发时的内存。

旧任务最终七项均完整：周报在同一F0001改到下周一十点，小林和其余六条保留；两万元预算未批准，与报价任务分开保存。改期正文有重复，旧日期明确属于变更前历史。

混合五项中四项完整、一项不完整：报告改期、新培训、预算35000未批准、报价任务正确；资产核对在同一F0002由杜凯改为程然，但输出仅写“截止时间和其他安排不变”，替换掉了原“周五中午十二点”。旧期限在事件日志中仍可查，最终稿未保留，不能算通过。

真实开场按相同九项要求为4完整、2部分、1遗漏、2失真。资金来源不再误写员工工资，但“房子已到期”变成“是否已到期”，公司成本压力被转成员工成本压力；仍漏相对吸引力，含混词被当成具体条件，尾批重复三个旧观点。质量并未随着提交修复稳定提高。

这不是通用准确率，也不证明完整66分钟、多人独立会议或ASR/C1并发通过。会后时间只包含已有事实排版，没有额外报告模型调用。

## 证据边界与收场决定

初版28先跑15次调用：开场5次全部保存，任务7次中的最后一次、混合3次中的后两次因“已有 F编号”格式被拒。最终28b只增加五行前缀兼容，模型提示/参数没有改动，再跑任务和混合共10次调用。总计25次真实请求，失败记录也保留。

开场是在初版适配器上实测。用最终适配器逐次重解析这五次原始回复，全部补丁和每步事实库与原结果一致，均未触发最后增加的前缀兼容分支；没有再次运行开场。

本地代码及回归可归档提交，固定工作流作为后续开发方向保留。当前仅适合作为人工复核的草稿，未晋升产品默认；本轮不再增加提示变体或改造 Agent。
